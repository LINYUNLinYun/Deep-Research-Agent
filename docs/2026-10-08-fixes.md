# 2026-10-08：证据、压缩与对抗链路修复

本次复现问题：`美股近一个月大涨的原因分析`。

## 原因与改动

- Researcher 未使用压缩器；旧硬截断可能丢掉原始任务和整组工具结果。现在在模型调用前压缩工具正文，保留工具调用配对及原始 trajectory，兜底截断不修改调用方数据。
- 重写报告后来源目录重新编号，旧草稿引用及 worker 的局部编号可能指向另一条来源。现在按稳定来源身份重映射旧引用，去掉 worker 的局部编号；重复 URL 的精确 VERIFY 证据会合并到目录。
- 来源仅按权威性排序，香港、无锡 CPI 等无关材料可能进入美股报告。现在加入主题/国家筛选；相对月度查询按最近 30 天判断，区间外及日期不明材料明确标注，来源日期传给合成、审查和修复模型。
- Critic 五维度串行调用，首次评审及修复后复评容易超过 180 秒。现在五维度并行；同一轮仍独立保留每个维度的解析重试及错误。
- 修复员自检包含已回滚的历史操作，后续修复被历史错误连带拒绝。现在只评审当前事务；空 `after` 的精确删除补丁可以执行，新增来源明确保存 citation_id 和稳定身份。
- 对抗修复后没有重新验证证据、重新校准置信度。现在使用同一 confidence_basis 重新校准，避免重复折扣；模型评分或证据检查退步时回退。超时保留之前已采纳的报告及其评分，剩余时间不足时不启动下一轮。
- 证据检查器把千位逗号当成数字分隔，并把整篇来源任意位置的否定词用于当前论断。现在统一千位格式，只比较最相关来源句的否定词；没有数值的证据段不能支持数值论断。摘要缺少数字记为 unknown；同一数值表达明确冲突才记为 contradicted。
- VERIFY 的 JSON `confidence: 0` 曾回落到默认 0.6；现在保留明确的零值。相同论断只改变引用编号时不会重复补查，补查受累计预算约束。
- 单次 CLI 运行同时保存 Markdown 与结构化 JSON，记录修复前后各维度、证据数量、置信度、采纳/回退原因；预算遥测使用实际追踪器，每个新查询重置。
- 同步项目现有的 Red/Blue → Critic/Repairer 命名变更；Critic 使用 MiMo，Repairer 使用 DeepSeek。

## 置信度的解释

报告置信度是启发式校准值，不能把它解释为已证明的正确概率。当前公式为：`confidence_basis × (0.5 + 0.5 × support_rate)`。Critic 的 0–10 维度评分单独展示，不直接代替报告置信度。

回归测试用同一来源修正错误营收数值，验证证据支持增加时置信度可从 0.40 升到 0.80。真实检索中的来源缺失、口径不一致或新增矛盾可能使修复不被采纳；不能仅为提高评分降低证据门槛。

结论：本次解决了已复现的压缩、引用错位、自检污染、补丁删除、误判及置信度未重算等程序问题；对抗机制现在可以在证据支持改善时重新计算更高的置信度，回归测试验证了该路径。真实美股样例尚未证明对抗修复提高置信度：检索与报告仍有证据缺口，最终实现的是拒绝更差修复并保留原报告。不能把多轮研究结果之间的差异归因于对抗机制，也不能把通过程序测试等同于报告事实已全部核实。
